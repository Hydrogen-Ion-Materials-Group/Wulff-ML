## Installation details

### Tested software versions

Wulff-ML was developed and tested with the following versions. The complete dependency list is in [`requirements.txt`](../requirements.txt).

| Package | Version |
|---|---:|
| Python | 3.13.8 |
| XGBoost | 3.2.0 |
| scikit-learn | 1.7.2 |
| pandas | 3.0.3 |
| NumPy | 2.4.6 |
| SHAP | 0.51.0 |
| Optuna | 4.9.0 |
| pymatgen | 2026.5.4 |
| matminer | 0.10.1 |

If dependency-version conflicts occur, install the versions specified in the requirements file:

```bash
pip install -r requirements.txt -e .
```

### Editable installation

The installation must be editable (`pip install -e .`), because the package reads input data from, and writes generated files to, the cloned repository. It also makes the `wulff-predict` and `wulff-key` command-line tools available.

### XGBoost version

**Use XGBoost 3.2.0. Other versions have not been validated for this workflow.**

XGBoost 3.4 revised the absolute-error objective. With the hyperparameters used here, particularly `gamma=0.1`, training with XGBoost 3.4.1 stopped improving after approximately 150 rounds. The resulting model did not split on any Miller-index features, causing all facets of a compound to receive the same predicted surface energy.

Setting `gamma=0` restored the expected behavior in our test. However, the hyperparameters were optimized with XGBoost 3.2.0, which is therefore pinned in `setup.py` and `requirements.txt`.

### Saved models

Pickled models in `models/` depend on the XGBoost and scikit-learn versions used to create them. If a saved model cannot be loaded, `wulff-predict` automatically retrains it. Models can also be regenerated by running step `02`.

## Materials Project API key

Downloading bulk descriptors from the Materials Project requires a free API key. The key is needed by `wulff-predict` and by analysis steps `01`, `04` (Experiment 4), and `08`.

### First use

No manual configuration is needed. When the key is required for the first time, the program prompts for it in the terminal:

1. Log in or register at the [Materials Project API page](https://next-gen.materialsproject.org/api).
2. Copy your API key.
3. Paste it into the terminal when prompted. The key is not displayed while you paste it.

After validation, the key is stored outside the repository at:

```text
~/.wulff_ml/mp_api_key
```

The file is readable only by the current user, and the key is requested only once. A key that could not be validated (for example, without an internet connection) is used for the current run only and is not saved.

### Managing the saved key

```bash
wulff-key             # Enter or replace the saved key
wulff-key --show      # Show the key in masked form
wulff-key --forget    # Delete the saved key
```

### Environment variable

Alternatively, set the `MP_API_KEY` environment variable. It takes priority over the saved key and is useful on systems without an interactive terminal, such as job schedulers.

```bash
# Linux / macOS
export MP_API_KEY="your_key_here"

# Windows
setx MP_API_KEY "your_key_here"
```

On Windows, restart the terminal after running `setx`.

All analysis steps other than those listed above run offline using the files in `data/raw/`. Without an API key, step `04` skips Experiment 4 and runs the remaining analyses.

## Predicting compounds

The `wulff-predict` command predicts the surface energies of the requested compounds and constructs their Wulff shapes. It requires Materials Project IDs (for example, `mp-149`), which can be found through the [Materials Project database](https://next-gen.materialsproject.org/materials).

```bash
# Enter Materials Project ID(s) interactively
wulff-predict

# Provide IDs directly
wulff-predict mp-1077900 mp-21119

# Read IDs from a text file
wulff-predict --file ids.txt

# Predict surface energies without constructing Wulff shapes
wulff-predict mp-149 --no-wulff

# Choose an output directory
wulff-predict mp-149 --out my_results
```

Multiple IDs can be separated by spaces, commas, or new lines.

The first run requests an API key (if one has not already been saved) and trains the model using the bundled DFT data. Training usually takes up to a few minutes. Subsequent runs load the saved model.

Surface energies are predicted for the 35 Miller indices represented in the training set (maximum index 2).

### Prediction outputs

By default, results are written to `results/predict/<date_time>/`. Use `--out` to specify a different output directory.

| Output | Description |
|---|---|
| `gamma_predictions.csv` | Predicted surface energy for every facet, in eV/Å² and J/m² |
| `wulff/area_fractions_wulff.csv` | Wulff-shape area fraction of every facet |
| `wulff/<mp_id>_<formula>_wulff.*` | Wulff shape saved as PNG, PDF, and SVG, plus a text-free `_raw.png` |
| `wulff/<mp_id>.cif` | Crystal structure used for the Wulff construction |

A summary of the lowest-energy facets and the largest Wulff-shape facets is also printed in the terminal.

### Python interface

The same workflow can be called from Python:

```python
from wulff_ml.prediction import predict_compounds

gamma_df, wulff_df, out_dir = predict_compounds(
    ["mp-1077900", "mp-21119"]
)
```

## Running the complete analysis

Run the full analysis pipeline in sequence with `python run_all.py`. Individual steps can be selected, resumed, or skipped:

```bash
python run_all.py                  # Run all steps in order
python run_all.py --only 02 06     # Run only the selected steps
python run_all.py --from 05        # Resume from step 05
python run_all.py --skip 01 08     # Skip the selected steps
python run_all.py --force-cache    # Ignore cached results
python run_all.py --cache-status   # Show cache status and exit
```

Each analysis step can also be run directly. For example:

```bash
python scripts/02_train_model.py
```

To train the main model and generate its SHAP figures without a Materials Project API key:

```bash
python run_all.py --only 02 06
```

### Analysis pipeline

| Step | Script | Description |
|---:|---|---|
| 01 | `01_prepare_features.py` | Fetch bulk descriptors from the Materials Project and add Magpie features* |
| 02 | `02_train_model.py` | Train the main XGBoost model and predict γ for all compound–facet pairs |
| 03 | `03_cross_validation.py` | Compare grouped and random splits; run 5-fold CV and composition-grouped validation |
| 04 | `04_hkl_analysis.py` | Broken-bond P(h,k,l) analysis using models A, B, and C* |
| 05 | `05_element_split.py` | Hold out entire elements (default: Cu and Ni) to test extrapolation |
| 06 | `06_shap_analysis.py` | Generate SHAP beeswarm and dependence plots |
| 07 | `07_multimodal_validation.py` | Compare XGBoost with linear regression, random forest, LightGBM, CatBoost, and extra trees |
| 08 | `08_wulff_prediction.py` | Construct Wulff shapes and calculate facet area fractions* |
| 09 | `09_data_ablation.py` | Generate learning curves using 10–100% of the training compounds |
| 10 | `10_feature_ablation.py` | Perform melting-point ablation, leave-one-group-out analysis, and forward group selection |
| 11 | `11_optuna_tuning.py` | Run Bayesian hyperparameter search; values are printed, but `config.py` is not modified |
| 12 | `12_ale_interaction.py` | Calculate the SHAP group-interaction matrix and top-30 pairwise heatmap (Plot A) |
| 13 | `13_pair_wise_interaction_filter.py` | Generate the top-30 heatmap after removing zero-interaction features (Plot B) |

`*` Requires a Materials Project API key (step `04` only for Experiment 4).

Step `08` uses predictions generated by step `02`. Step `13` reuses the cached results from step `12`.

Generated results are saved in `results/`, figures in `figures/`, and trained models in `models/`. These directories, along with `cache/`, are created automatically on the first run.

## Data

### Data sources

The DFT surface energies are taken from the [SurFF database](https://doi.org/10.1038/s43588-025-00839-0). The full dataset is available on [figshare](https://doi.org/10.6084/m9.figshare.26395756), and the SurFF code is available on [Zenodo](https://doi.org/10.5281/zenodo.15480651). Bulk-material descriptors are obtained from the [Materials Project](https://materialsproject.org/).

If you reuse the data, please cite the relevant sources and follow their terms of use. See the [references](../README.md#references).

### Included input files

All input files are included in `data/raw/`.

| File | Contents |
|---|---|
| `training_data.csv` | DFT targets (`mp_id`, `hkl`, `gamma_eV_per_ang2`); 13,155 rows |
| `03_DFT_surff_bulk_descriptors_2575.csv` | Bulk descriptors for the training compounds; 2,573 rows |
| `05_DFT_surff_bulk_descriptors_2575_magpie.csv` | File 03 with 132 additional Magpie features; used by steps 02–13 |
| `04_wulff_to_pred_bulk_data.csv` | Bulk descriptors for the three compounds used for prediction |
| `06_wulff_to_pred_bulk_descriptor_magpie.csv` | File 04 with 132 additional Magpie features; used by step 02 and the P(h,k,l) analysis |
| `prediction_mpids.csv` | Materials Project IDs and formulas for compounds to be predicted; input to step 01 |

### Dataset summary

The training set contains:

- **2,573 compounds:** 45 unary, 843 binary, and 1,685 ternary compounds.
- **51 elements** in total.
- **35 distinct Miller indices**, with a maximum index of 2.
- **13,155 DFT surface-energy targets.**

Two compounds in `training_data.csv` (`mp-30356` and `mp-30428`) do not have corresponding entries in the descriptor files. Their target values are retained, and their bulk features are median-imputed.

Files `04` and `06` contain three CeNiSn polymorphs (`mp-1077900`, `mp-1226819`, and `mp-21119`), which are the compounds predicted by step `02`. For other compounds, use `wulff-predict`; it downloads the required descriptors and does not rely on these files.

## Method

### Features and model

- **174 input features:** 157 bulk and composition descriptors (structural, energetic, electronic, elastic, composition-weighted, and Magpie features) and 17 Miller-index features.
- The Materials Project `weighted_surface_energy` columns are excluded to prevent target leakage.
- **Regressor:** XGBoost with the absolute-error objective and early stopping (120 rounds).
- Hyperparameters are defined in `wulff_ml/config.py`.

### Training and evaluation

- Data are split by compound (`mp_id`), so no compound appears in more than one of the training, validation, and test sets (approximately 64/16/20%).
- A random row-wise split can place facets of the same compound in both training and test sets, inflating apparent performance. Step `03` quantifies this effect.
- Random seed: `22` (`RANDOM_STATE` in `wulff_ml/config.py`).
- Evaluation metrics: MAE, R², Spearman's ρ, and Kendall's τ.
- `inf` and `NaN` values are replaced with training-set medians. The same medians are applied to validation, test, and prediction data.

### Interpretability and Wulff construction

- Feature importance is analyzed using SHAP values and SHAP interaction values.
- Wulff shapes are constructed from the predicted γ(hkl) values using [pymatgen](https://pymatgen.org/).

### Units

Surface energies are reported in **J/m²** in plots, printed metrics, and output files. The DFT training targets are stored internally in **eV/Å²**. The conversion is

1 eV/Å² = 16.0218 J/m²

and is defined in `wulff_ml/units.py`.

### Figure outputs

Figures are saved in four formats by `save_figure`:

- `name.png` — 600 dpi
- `name.pdf`
- `name.svg`
- `name_raw.png` — the same geometry with all text removed, for compositing in image editors

### Caching

Expensive calculations are cached in `cache/`. Each cache key is based on a hash of the function and all its inputs. Changing an input or parameter triggers recalculation automatically. Failed downloads are not cached.

Inspect or clear the cache with:

```bash
python run_all.py --cache-status  # List cached results
python clear_cache.py train_xgb   # Clear one task
python clear_cache.py             # Clear everything (asks for confirmation)
```

## Notes and limitations

- The model is trained on 2,573 compounds containing 51 elements, predominantly binary and ternary intermetallics. Predictions for compositions, structure types, or Miller indices far outside this range, including indices above 2, are extrapolations. Step `05` evaluates extrapolation to unseen elements.
- Predicted surface energies inherit the DFT settings, slab construction, and referencing scheme of the SurFF database.
- Re-running step `01` or `wulff-predict` with a newer Materials Project release may change descriptor values. The files in `data/raw/` are the exact inputs used in this work.
- The original scripts used two slightly different descriptor-group definitions. Both are retained in `wulff_ml/feature_groups.py` as `FEATURE_ABLATION_GROUPS` and `ALE_GROUPS`.
- `12_ale_interaction.py` is a historical filename; it computes SHAP interaction values.
